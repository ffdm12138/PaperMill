# Repository contract for coding agents

Read `docs/PROJECT_STATUS.md`, `docs/PROJECT_CONTRACT.md`, `docs/TESTING.md`,
`docs/SCRIPT_USAGE.md`, and `README.md` before changing ingest or writing code.

## Active architecture

- Metadata schema v2.0 is the immutable citation record. It contains only
  bibliographic facts and provider/raw-record provenance. It never contains
  `paper_name`, LLM content, or workflow match state.
- `<paper_number>.metadata_match.json` is the sole PDF identity decision.
  `<paper_number>.metadata_freeze.json` closes over Metadata, PDF, match receipt,
  citation artifacts, and source records. Normal services never rewrite a
  frozen closure.
- Catalog schema v3.2 is the only active Catalog. It is the complete LLM content
  dossier: trusted source abstract, Chinese summary, one-sentence summary,
  context, question, methods, data, findings, mechanisms, limitations,
  terminology, figures/tables, evidence refs, writing value, screening, and
  `paper_name`. It is never a citation source.
- `paper_number` is the permanent 16-digit machine identity. Every active
  pre-commit workspace is `data/paper_raw/<paper_number>/` and every main asset
  has the numeric prefix. `paper_name` is generated by the Catalog task from the
  frozen `<year>_<first-author>_` prefix plus `content_title_zh`.
- Conversion requires only an attached PDF. Local-PDF ingest may convert before
  Metadata resolution. Catalog generation requires Metadata frozen plus current
  conversion. Formalize requires both Metadata and Catalog frozen.
- Formalize is read-only except for the numeric formalization plan and nested
  status update. It never renames, installs, changes ledger paths, Metadata, or
  Catalog. Commit alone renames copied assets inside hidden staging.
- Commit uses an external durable journal under `data/transactions/commit/`,
  atomically installs `data/papers/<paper_name>/`, activates the ledger, requests
  Catalog-folder reconciliation, verifies frozen hashes, then deletes raw. Commit and
  rollback public entry points automatically discover and resume their sole
  valid active journal; conflicts and ambiguous journals fail closed.
- Each formal paper owns its independent Catalog. Catalog folders are the only
  browsing index; members are controlled directory links to complete formal
  paper directories. `all` contains every active paper, `_pending` contains
  papers lacking current LLM decisions, and Chinese keyword categories overlap.
- Citation, CSL, BibTeX, APA, author-year keys, and references are generated
  only from Metadata. Catalog is used only for discovery and understanding.

## Lock order

Acquire only the needed ordered subset:

`transaction lock(s) -> paper_raw/.paper_raw_write.lock -> ledger lock -> workspace lock(s) -> papers install lock -> category lock`

Multiple paper locks are acquired by ascending numeric `paper_number` and
released in reverse order. Transaction locks live at
`data/transactions/locks/<paper_number>.lock`. Never hold the ledger lock during
PDF/tree copies. Never acquire a lower-ranked lock while holding a higher one.

## Runtime and safety boundaries

- Runtime data includes `data/raw`, `data/paper_raw`, `data/papers`,
  `data/transactions`, generated `data/catalog` folders/state/ledger, `output`,
  `reports`, and `write/jobs`. Do not modify real runtime data in agent work.
- Tests use `tmp_path`, fake providers, fake MinerU, mock transports, and
  isolated ledger/index roots. Never use real network, real MinerU, or real
  migration `--apply` during agent acceptance.
- Only Metadata v2.0 and Catalog v3.2 are supported. Do not add schema migration,
  compatibility fallback, or readers for older Metadata, Catalog, or workspace
  layouts; unsupported inputs must be regenerated outside the active pipeline.
- Do not implement Sci-Hub, RAG, embeddings, a vector database, or a built-in
  LLM client. Initial Catalog screening remains `read_decision="pending"`.
- Never derive paper numbers by directory scans; use `PaperNumberLedger`.
- Never parse `.paper.number` with `Path.stem`; remove the full suffix.

## Verification and delivery

Use the Python environment at
`C:\Users\Admin\.conda\envs\mineru\python.exe` when `python` is not on PATH.
Set `PYTHONIOENCODING=utf-8` and `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` for tests.

For broad changes run targeted tests, then contract/hygiene, unit/integration,
slow tests, compileall, and finally:

```text
python scripts/agent_acceptance.py --full
```

The authoritative packer is `scripts/pack_repo.py`. Both default audit and
source snapshots are runtime-zero. Audit may include dirty lightweight source
and fixtures only from `tests/fixtures/synthetic_library`; it never samples
real runtime workspaces. Verify the ZIP exists, opens, contains source/tests/
docs/migrations, and its manifest reports `runtime_files_included=0`.

Do not run `git reset`, `git checkout`, `git clean`, `git add`, `git commit`, or
`git push` unless the user explicitly requests it. Preserve unrelated dirty
worktree changes.

## Test runtime workspace hygiene

- Windows paths must never be embedded in `PYTEST_ADDOPTS`, `addopts`, or any
  shell command string. pytest 9.x uses `shlex.split(posix=True)` to parse
  `PYTEST_ADDOPTS`, which strips every backslash from Windows paths — turning
  `C:\Users\Admin\...\cache` into `C:UsersAdmin...cache` (a relative path on
  the C: drive that creates directories at the drive root).
- Test subprocesses must use argument lists (`list[str]`), `shell=False`, and
  an independent `env` dict. Paths are delivered exclusively through the `env`
  parameter of `subprocess.run` / `subprocess.Popen`. Never set `PYTHONPYCACHEPREFIX`,
  `TMP`, `TEMP`, or `cache_dir` via inline shell assignment, `bash -c`, or
  `cmd /c`.
- All test groups must create an isolated workspace through
  `TestRuntimeWorkspace` from `scripts/test_runtime_workspace.py`.
  The context manager guarantees cleanup on success, failure, exception, and
  interrupt. Workspaces live under the system temporary directory and carry a
  machine-readable `.mineru-test-workspace.json` marker for stale detection.
- Never create test caches on a drive root (`C:\`), the repository root, or
  inside real `data/` directories.
- Acceptance detects pollution but never auto-deletes it. Pre-flight fails
  closed on ANY existing `__pycache__` / `.pyc` / legacy root caches / unowned
  stale workspaces. Post-flight uses path-set diffs against the pre-flight
  snapshot and reports only items created during that run.
- Test success is not acceptance success. If the run leaves behind `.pyc` files,
  `__pycache__` directories, pytest `basetemp` residue, or legacy flattened-root
  cache directories, the acceptance gate must fail.
- Workspace cleanup failure preserves the marker (updated with failure status)
  and keeps ``_root`` so the path can be reported.  If cleanup fails, acceptance
  must fail.
- Only directories with a valid `.mineru-test-workspace.json` marker, matching
  repo, and dead PID are safe for automatic cleanup.  Legacy flattened-root
  caches require exact name match, valid `CACHEDIR.TAG` with pytest signature,
  and standard pytest cache structure.
- Syntax gate uses ``compile(source, filename, "exec")`` — never writes bytecode.
- Cleanup commands (dry-run by default):
  ```powershell
  python scripts/cleanup_test_caches.py
  python scripts/cleanup_test_caches.py --legacy-flattened-root
  python scripts/cleanup_test_caches.py --legacy-flattened-root --apply
  ```

## Operational ingest paths

Manual PDF queue: `data/raw/` is a queue. Normal staging uses
`stage_raw_pdfs_to_paper_raw.py --move --apply`, then
`convert_paper_raw_gpu.py`, then
`resolve_paper_raw_metadata.py`; the resolver
uses converted Markdown as its primary front-matter input. Network Metadata
uses `stage_network_metadata_to_paper_raw.py`, then `fetch_pdf_for_paper_raw.py`.
Metadata-only fetch reads DOI only from Metadata, never `doi.csv`, and attaches
as `<paper_number>.pdf`. The resolver chain is original link, OA, publisher,
then explicit header-based DOI landing fallback at `https://doi.org/{doi}`.
Normal conversion uses `--only-convertible` and does not require matched Metadata.

## Keyword metadata discovery concurrency rule

Broad discovery selects 3–8 focused Chinese classification notebooks through
`discover_papers_concurrent.py` with 3–4 workers. HTTP lanes are concurrent;
all allocation and final duplicate guard work remains inside the
allocator write critical section protected by `.paper_raw_write.lock`. Never bypass the
allocator or precompute paper numbers.

### Dual-lane keyword notebooks

Refresh starts from the first provider cursor for each run; Backfill resumes a
trusted cursor. Durable pages and `keyword_notebooks` retain fetched candidates
before cursor CAS. Use `manage_discovery_keywords.py` for notebook operations.
Pending work uses leases and DOI/title-resolution locks; `max_candidates` is a
drain budget and never discards fetched candidates.

The page journal is the sole production candidate carrier.
`PendingCandidateStoreV4` is a migration-only transitional drain channel:
written only by the v4 migrator, drained by normal discovery runs, and its
directory removed by `--clean-legacy` once empty (see
`docs/ADR_DISCOVERY_V4_MIGRATION_FINAL.md`).

Only keyword notebook schema v4 is active. One notebook owns one Chinese
classification identity (`keyword_zh`) and multiple curated `search_queries`.
Every enabled Chinese and English query runs against both OpenAlex and
Crossref, but query text never becomes a Catalog category, directory, task
identity, or classification hash input. Active discovery never expands queries
at runtime. Missing, corrupt, legacy, or bilingual-incomplete enabled notebooks
fail before provider I/O; only an explicitly disabled notebook is a successful
skip. Use `--keyword-zh` to select notebooks and `--dry-run` for a read-only
provider-lane plan.

Enabled notebooks must always be bilingual-ready. New incomplete definitions
are disabled drafts, and store-level enable/mutation checks fail closed if
readiness would be lost. `audit_discovery_keyword_index_sources.py` is strict
v4 and read-only. `recover_discovery_keyword_notebooks.py --inspect` is the
only recovery mode for legacy v3 notebooks; recovery apply is unavailable until a plan-bound writer
is independently verified.

The production set contains five enabled Chinese keyword notebooks; legacy v3 notebooks must be migrated to v4 before discovery can use them.
Inventory and a fixed reviewed mapping/plan precede any authorized apply, and
the applied transaction preserves queries, provider generation/signature,
cursors, generation history, and page journals. Real mapping and plan evidence
belongs in ignored operator/runtime state, never active source or snapshots;
only safe examples may live under `migrations/`. The concurrent `--dry-run`
must report every notebook/provider lane with generation, request signature,
refresh pages, backfill pages, worker count, and page budget. It performs no
provider I/O, cursor or page-journal writes, paper allocation, notebook
mutation, or Catalog mutation; real network search requires an explicit user
command after the read-only checks.

Discovery execution contract: refresh and backfill page budgets are
independent -- refresh is bounded by its own window (`refresh_pages`) and
never consumes the backfill page budget (`max_pages_total`), so a hybrid
refresh lane cannot starve backfill. `--until-exhausted` is decoupled from
`--max-pages-total`: it requires at least one safety valve
(`--max-pages-total` OR `--max-provider-requests-total`); giant-integer
simulation of unbounded runs is forbidden. Reaching either valve is a clean
`budget_reached` stop (resumable from the same cursor), never a provider
failure or `exhausted`. All OpenAlex/Crossref HTTP -- discovery pages, title
resolution, metadata resolution, DOI scope verification, and taxonomy fetch --
goes through the unified `ProviderClient` (shared per-provider limiter,
retry/backoff/Retry-After, circuit breaker, batch-wide request budget,
telemetry); no business module may call `requests.get`/`httpx.get` directly.
Lane stop reasons use the frozen `STOP_REASONS` vocabulary; `exhausted=True`
requires `exhaustion_evidence` and is never written on transient failure,
timeout, 429, 5xx, SSL, budget, or interrupt. The batch report carries
`provider_requests` telemetry (attempted/retried/succeeded/failed) and
aggregate section totals are conservation-checked against lane counters.

Successful final acceptance must include the literal output lines
`[OK] agent acceptance passed` and `[OK] Packed: mineru_snapshot.zip`.

Enabled notebooks must also bind a non-sentinel, taxonomy-resolved relevance
profile. Missing and legacy/profile-unbound profiles fail before provider I/O.
Profile replacement closes every old-profile nonterminal relevance verdict
(`profile_unbound`, `passed`, and `verification_deferred`) using durable
keyword/request/candidate profile identity; it never equates provider lane
generation with relevance generation. The drain index and durable claim both
require the active profile hash. Only one relevance-profile transaction may be
`applying`, and discovery shares its exclusion lock.

Recovery treats every journal as untrusted input. Commit reconciliation must
receive trusted transaction, `paper_raw`, and `papers` roots explicitly and
must finish path, identity, symlink, alias, filesystem, and index preflight
before its first mutation; roots are never derived from journal fields.
`.import_status.json` may be changed only through the canonical locked
read-modify-write service. PDF transport is direct-first, validates the
requested PDF/HTML content, falls back through the configured proxy on a
retryable content mismatch, and keeps direct/proxy timeouts independent.
Persisted fetch reports recursively strip URL query strings, including URLs
embedded in exception or reason text. Discovery export idempotency requires a
matching manifest and JSONL identity, hash, size, and record count. Snapshot
packing fails on every selected-file omission or change. Process ordering
tests use events/queues or other synchronization primitives, never fixed
sleeps. After changes, run acceptance, the authoritative packer, and inspect
an unpacked snapshot.

Run the default fast gate first. Use `--process` for real process behavior,
`--stress` for amplified races, and `--full` for releases or broad refactors.
No real-process test may lack the `process` marker; every process test must
clean its complete process tree. Keep each contract authoritative in one
layer. Runtime-zero rules live in `src/services/repository_hygiene.py`;
`source_records` and its targets must never be symlinks. After every change,
run the packer and inspect an unpacked snapshot.

For every completed code change, both the fast gate and full gate must finish,
then `scripts/pack_repo.py` must generate a verified runtime-zero snapshot.
`AGENTS.md` and `CLAUDE.md` must remain byte-for-byte identical.

## Discovery staging ownership boundary

Discovery duplicate lookup covers both `paper_raw` and active `papers`; a valid
formal primary has priority. Formal projections are generation-bound and reload
only when the durable formal publication generation changes. The generation is
stored in `data/papers/.formal_publication_state.json` and binds every active
formal's metadata/catalog/manifest hashes; each staging batch rechecks that
closure before candidate decisions. One discovery batch
owns one `DiscoveryStagingContext`, one cold Registry build, one
`JournalDrainIndex`, and one bounded single-consumer staging queue. Repair backlog
members are never scanned per candidate: batch-boundary probes are capped at 20,
while an actual DOI/identity hit is always revalidated live. Page claims and
commits are batched, staging lock epochs contain at most 16 candidates, and every
new paper still has separate reserved and metadata_staged ledger checkpoints.
Correctness caches are file-generation/fingerprint bound; pure TTL caches are
forbidden.

`PaperNumberLedger` owns only permanent number and raw/formal lifecycle state.
`WorkspaceEvidence` reads single-workspace facts once; `WorkspaceReadiness`
applies only the explicit `stage_manifest.workflow_path` profile and fails
closed for missing or unknown profiles. `WorkspaceRegistry` is the sole DOI
and discovery-identity disk scan entry point; incremental refresh is
copy-on-write and publishes only a fully validated replacement snapshot.
`DiscoveryStageTransaction` is the sole network-staging coordinator under the
raw write lock. The allocator contains only generic workspace primitives, and
`pending_queue.py` contains only candidate-journal orchestration. The retired
DuplicateIndex/WorkspaceIndex disk refresh APIs and `workspace_refresh.py` do
not have compatibility fallbacks.

`reserved` workspaces may lack staging evidence and remain unsettled;
`metadata_staged` asserts a complete profile closure, so any missing metadata,
source record, discovery receipt, stage manifest, import status, or marker is
`repair_required`. Discovery identities use the sole entity key
`(identity_key, paper_number)`, allowing multiple provider identities per paper
through freeze. Refresh consumes the locked ledger view and publishes
atomically. Successful staging directly publishes its validated record without
post-refresh. Each candidate loads the ledger once; a new record keeps two
durable saves: reservation before writes and `metadata_staged` after validation.

A Registry snapshot is a performance cache, not permanent truth. Refresh
compares every record's in-memory ledger state, folder, and expected scope and
target-rescans only changed paper numbers. Before reuse or duplicate decisions,
DOI/identity matches are live-revalidated; damaged `metadata_staged` evidence
returns `repair_required`. Record replacement removes all old DOI/identity
projections, including formal refs after active rollback. Adapter reports keep
`actual_allocated` exclusive to new staging and report reuse separately.
