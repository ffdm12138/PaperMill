# Repository contract for coding agents

Read `docs/PROJECT_STATUS.md`, `docs/PROJECT_CONTRACT.md`, `docs/TESTING.md`,
`docs/SCRIPT_USAGE.md`, and `README.md` before changing ingest or writing code.

## Active architecture

- Metadata schema v2.0 is the immutable citation record. It contains only
  bibliographic facts and provider/raw-record provenance. It never contains
  `paper_id`, LLM content, or workflow match state.
- `<paper_number>.metadata_match.json` is the sole PDF identity decision.
  `<paper_number>.metadata_freeze.json` closes over Metadata, PDF, match receipt,
  citation artifacts, and source records. Normal services never rewrite a
  frozen closure.
- Catalog schema v3.2 is the only active Catalog. It is the complete LLM content
  dossier: trusted source abstract, Chinese summary, one-sentence summary,
  context, question, methods, data, findings, mechanisms, limitations,
  terminology, figures/tables, evidence refs, writing value, screening, and
  `paper_id`. It is never a citation source.
- `paper_number` is the permanent 16-digit machine identity. Every active
  pre-commit workspace is `data/paper_raw/<paper_number>/` and every main asset
  has the numeric prefix. `paper_id` is generated by the Catalog task from the
  frozen `<year>_<first-author>_` prefix plus `content_title_zh`.
- Conversion requires only an attached PDF. Local-PDF ingest may convert before
  Metadata resolution. Catalog generation requires Metadata frozen plus current
  conversion. Formalize requires both Metadata and Catalog frozen.
- Formalize is read-only except for the numeric formalization plan and nested
  status update. It never renames, installs, changes ledger paths, Metadata, or
  Catalog. Commit alone renames copied assets inside hidden staging.
- Commit uses an external durable journal under `data/transactions/commit/`,
  atomically installs `data/papers/<paper_id>/`, activates the ledger, requests
  Catalog-folder reconciliation, verifies frozen hashes, then deletes raw. Commit and
  rollback public entry points automatically discover and resume their sole
  valid active journal; conflicts and ambiguous journals fail closed.
- Each formal paper owns its independent Catalog. Catalog folders are the only
  browsing index; members are controlled directory links to complete formal
  paper directories. `all` contains every active paper, `_pending` contains
  papers lacking current LLM decisions, and Chinese keyword categories overlap.
- Citation, CSL, BibTeX, APA, author-year keys, and references are generated
  only from Metadata. Catalog is used only for discovery and understanding.

## Lock order

Acquire only the needed ordered subset:

`transaction lock(s) -> paper_raw/.paper_raw_write.lock -> ledger lock -> workspace lock(s) -> papers install lock -> category lock`

Multiple paper locks are acquired by ascending numeric `paper_number` and
released in reverse order. Transaction locks live at
`data/transactions/locks/<paper_number>.lock`. Never hold the ledger lock during
PDF/tree copies. Never acquire a lower-ranked lock while holding a higher one.

## Runtime and safety boundaries

- Runtime data includes `data/raw`, `data/paper_raw`, `data/papers`,
  `data/transactions`, generated `data/catalog` folders/state/ledger, `output`,
  `reports`, and `write/jobs`. Do not modify real runtime data in agent work.
- Tests use `tmp_path`, fake providers, fake MinerU, mock transports, and
  isolated ledger/index roots. Never use real network, real MinerU, or real
  migration `--apply` during agent acceptance.
- Only Metadata v2.0 and Catalog v3.2 are supported. Do not add schema migration,
  compatibility fallback, or readers for older Metadata, Catalog, or workspace
  layouts; unsupported inputs must be regenerated outside the active pipeline.
- Do not implement Sci-Hub, RAG, embeddings, a vector database, or a built-in
  LLM client. Initial Catalog screening remains `read_decision="pending"`.
- Never derive paper numbers by directory scans; use `PaperNumberLedger`.
- Never parse `.paper.number` with `Path.stem`; remove the full suffix.

## Verification and delivery

Use the Python environment at
`C:\Users\Admin\.conda\envs\mineru\python.exe` when `python` is not on PATH.
Set `PYTHONIOENCODING=utf-8` and `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` for tests.

For broad changes run targeted tests, then contract/hygiene, unit/integration,
slow tests, compileall, and finally:

```text
python scripts/agent_acceptance.py --full
```

The authoritative packer is `scripts/pack_repo.py`. Both default audit and
source snapshots are runtime-zero. Audit may include dirty lightweight source
and fixtures only from `tests/fixtures/synthetic_library`; it never samples
real runtime workspaces. Verify the ZIP exists, opens, contains source/tests/
docs/migrations, and its manifest reports `runtime_files_included=0`.

Do not run `git reset`, `git checkout`, `git clean`, `git add`, `git commit`, or
`git push` unless the user explicitly requests it. Preserve unrelated dirty
worktree changes.

## Operational ingest paths

Manual PDF queue: `data/raw/` is a queue. Normal staging uses
`stage_raw_pdfs_to_paper_raw.py --move --apply`, then
`convert_paper_raw_gpu.py`, then
`resolve_paper_raw_metadata.py`; the resolver
uses converted Markdown as its primary front-matter input. Network Metadata
uses `stage_network_metadata_to_paper_raw.py`, then `fetch_pdf_for_paper_raw.py`.
Metadata-only fetch reads DOI only from Metadata, never `doi.csv`, and attaches
as `<paper_number>.pdf`. The resolver chain is original link, OA, publisher,
then explicit header-based DOI landing fallback at `https://doi.org/{doi}`.
Normal conversion uses `--only-convertible` and does not require matched Metadata.

## Keyword metadata discovery concurrency rule

Broad discovery uses 3–8 focused queries through
`discover_papers_concurrent.py` with 3–4 workers. HTTP lanes are concurrent;
all allocation and final duplicate guard work remains inside the
allocator write critical section protected by `.paper_raw_write.lock`. Never bypass the
allocator or precompute paper numbers.

### Dual-lane keyword notebooks

Refresh starts from the first provider cursor for each run; Backfill resumes a
trusted cursor. Durable pages and `keyword_notebooks` retain fetched candidates
before cursor CAS. Use `manage_discovery_keywords.py` for notebook operations.
Pending work uses leases and DOI/title-resolution locks; `max_candidates` is a
drain budget and never discards fetched candidates.

Successful final acceptance must include the literal output lines
`[OK] agent acceptance passed` and `[OK] Packed: mineru_snapshot.zip`.

Recovery treats every journal as untrusted input. Commit reconciliation must
receive trusted transaction, `paper_raw`, and `papers` roots explicitly and
must finish path, identity, symlink, alias, filesystem, and index preflight
before its first mutation; roots are never derived from journal fields.
`.import_status.json` may be changed only through the canonical locked
read-modify-write service. PDF transport is direct-first, validates the
requested PDF/HTML content, falls back through the configured proxy on a
retryable content mismatch, and keeps direct/proxy timeouts independent.
Persisted fetch reports recursively strip URL query strings, including URLs
embedded in exception or reason text. Discovery export idempotency requires a
matching manifest and JSONL identity, hash, size, and record count. Snapshot
packing fails on every selected-file omission or change. Process ordering
tests use events/queues or other synchronization primitives, never fixed
sleeps. After changes, run acceptance, the authoritative packer, and inspect
an unpacked snapshot.

Run the default fast gate first. Use `--process` for real process behavior,
`--stress` for amplified races, and `--full` for releases or broad refactors.
No real-process test may lack the `process` marker; every process test must
clean its complete process tree. Keep each contract authoritative in one
layer. Runtime-zero rules live in `src/services/repository_hygiene.py`;
`source_records` and its targets must never be symlinks. After every change,
run the packer and inspect an unpacked snapshot.

For every completed code change, both the fast gate and full gate must finish,
then `scripts/pack_repo.py` must generate a verified runtime-zero snapshot.
`AGENTS.md` and `CLAUDE.md` must remain byte-for-byte identical.
