# MinerU literature library

This repository manages a citation-safe literature library built from numeric
pre-commit workspaces and transactionally installed formal papers.

## Core model

- Metadata v2.0 is a frozen bibliographic record and the only citation source.
- Catalog v3.2 is a complete paper-content dossier for people and downstream
  models. It includes trusted source abstract, Chinese summary, question,
  methods, data, findings, mechanisms, limitations, terminology, figures,
  evidence, writing value, screening, and the semantic `paper_id`.
- `paper_number` is permanent. `paper_id` is human-readable and generated by
  the Catalog task. They are linked only by `paper_number`.
- `data/paper_raw/<paper_number>/` is the only pre-commit workspace. Formalize
  writes an installation plan; commit renames only inside hidden staging.

## Ingest

Manual PDF path:

```text
stage_raw_pdfs_to_paper_raw.py --move --apply
convert_paper_raw_gpu.py --all --apply
resolve_paper_raw_metadata.py --all-unmatched --apply --allow-network
freeze_paper_raw_metadata.py
prepare_paper_raw_catalog_task.py
# Catalog Skill writes complete Catalog v3.2
validate_paper_raw_catalog.py --apply
formalize_paper_raw.py --all-ready --apply
commit_paper_raw_to_papers.py --all-ready --apply
```

`data/raw/` is a queue. The resolver consumes converted Markdown after MinerU;
normal staging is always `--move --apply`. Normal conversion uses
`--only-convertible` and does not require Metadata matching first.

Network Metadata path stages DOI-backed citation Metadata first, fetches and
attaches the PDF, performs strict match/freeze, converts, then joins the same
Catalog/formalize/commit path. Local conversion may run before Metadata freeze.

All production commands support isolated roots where applicable. Tests and
agents must pass temporary `paper_raw`, `papers`, ledger, index, transaction,
and report paths; they must not use real network or MinerU.

## Writing

Writing selects by Catalog/`paper_number`, copies formal assets into
`write/jobs/<job_id>/article/<paper_number>/`, and generates BibTeX/citation
keys only from copied Metadata. It never infers citations from Catalog,
Markdown, a directory name, or `paper_id`.

## Rollback

Rollback is an external-journal transaction that restores the exact frozen
assets to a numeric raw workspace before removing the quarantined formal copy.
Its public entry point automatically resumes the sole valid active rollback
journal and fails closed on commit conflicts or ambiguous journals. Only
Metadata v2.0 and Catalog v3.2 are supported; older layouts must be regenerated
outside the active pipeline because this repository has no runtime migration path.

## Verification and packaging

```text
C:\Users\Admin\.conda\envs\mineru\python.exe scripts/agent_acceptance.py --full
C:\Users\Admin\.conda\envs\mineru\python.exe scripts/pack_repo.py
```

Default audit and source snapshots are runtime-zero. Audit includes dirty
lightweight source and synthetic fixtures only; it never samples real
`paper_raw`, `papers`, transactions, generated indexes/ledger, output, logs,
credentials, or writing jobs.

Commit recovery requires explicit trusted transaction, raw-workspace, and
formal-paper roots. PDF retrieval is direct-first with content-aware proxy
fallback and independently configured route timeouts; persisted diagnostics
strip URL queries recursively. Discovery exports and source snapshots are
accepted only after complete identity and byte-level integrity verification.
